# アカウント保存のエンドツーエンド暗号化（設計）

図・CSVをブラウザ内で暗号化してから Firestore に保存し、本人以外（Google・Firebase の管理者・
パスワードを盗んだ第三者）には中身を読めないようにする。評価はブラウザ内（Pyodide）で行うので、
サーバが中身を読む必要はない。

## 決めたこと

| 項目 | 方針 |
|---|---|
| 解除の方法 | ログインとは別の**暗号化パスフレーズ**が基本。**パスキー**（指紋・顔）でも解除できる |
| 鍵をなくしたとき | 初回設定で**回復キー**を発行し、控えてもらう。パスフレーズを忘れても回復キーで新しいパスフレーズを設定できる |
| 既存の暗号化されていないデータ | 初回設定のときに自動で暗号化して置き換える |
| 解除の保持 | 鍵はメモリにだけ置く。再読み込み・タブを閉じる・ログアウトで忘れる（毎回入力） |
| 第1段階の範囲 | 図とCSVの暗号化、パスフレーズ、回復キー、移行、Firestore ルールの強化 |

## 鍵の構成

```
暗号化パスフレーズ ──PBKDF2──▶ KEK(pass)     ─┐
回復キー           ──HKDF────▶ KEK(recovery) ─┼─ それぞれで MK を包む（wrap）
パスキー（PRF）    ──HKDF────▶ KEK(passkey)  ─┘
                                                │
                                MK（利用者の主鍵, AES-256）
                                                │ 項目ごとの鍵を包む
                         DEK（図・CSV 1件ごとの鍵, AES-256-GCM）
                                                │
                                   図・CSVの本文と名前を暗号化
```

- **MK**: 利用者ごとに1つ、ブラウザでランダムに作る。Firestore には包んだ形でしか置かない。
- **DEK**: 図・CSV 1件ごとにランダムに作り、MK で包んで同じドキュメントに置く。
  将来の共有（第3段階）では、この DEK を相手の鍵で包み直して渡す。
- **パスフレーズ**: PBKDF2-SHA256（WebCrypto 標準）。反復回数 600,000、ソルト 16バイト。
  12文字以上を求める。パスフレーズを変えても MK を包み直すだけで、データの再暗号化は不要。
- **回復キー**: ランダム 160ビットを、読み間違えにくい32文字（Base32、4文字ずつ区切り）で表示する。
- **パスキー**: WebAuthn の PRF 拡張で得た値から KEK を作る。パスキーごとに包んだ MK を持つ。
  PRF に対応しないブラウザ・端末では使えないので、パスフレーズは必ず残す。
- 暗号はすべて WebCrypto（AES-256-GCM、IV は毎回ランダム 12バイト）。
  AAD に `uid・コレクション名・ドキュメントID・形式の版` を入れ、ドキュメントの入れ替えや別人のデータへの付け替えを検知する。

## Firestore のデータ

```
users/{uid}/crypto/keyring
  v: 1
  pass:     { salt, iter, iv, wrappedMk }
  recovery: { iv, wrappedMk }
  passkeys: { <credentialId>: { prfSalt, iv, wrappedMk } }   … 第1b段階
  createdAt

users/{uid}/diagrams/{ランダムID}
users/{uid}/csvFiles/{ランダムID}
  v: 1
  wrappedDek: { iv, ct }
  iv, ct          … {"name": 名前, "content": 本文} を暗号化したもの
  updatedAt       … 平文（並べ替えに使う）
```

- 名前も暗号化する。そのため「名前で検索」「名前からドキュメントIDを作る」（今のCSV）はやめ、
  一覧を読んでブラウザ内で名前を復号して探す（件数は少ない想定）。
- 暗号化しても見えるもの: 件数、大きさ、更新日時。

## Firestore ルール

- `crypto/keyring` は本人だけが読み書きできる。項目は上の形に限る。
- `diagrams`・`csvFiles` は、項目が `v・wrappedDek・iv・ct・updatedAt` だけで、大きさの上限内のときだけ書ける。
  **平文の `name`・`content` を持つドキュメントは書けない**（移行のための削除は許す）。
- 今と同じく、本人かつメールアドレス確認済みが前提。

## 画面の流れ

1. ログイン後、初めてアカウント保存を使うとき → **初回設定**
   パスフレーズを2回入力 → 回復キーを表示（コピー・テキストで保存）→「控えました」を確認
   → 既存データを暗号化して置き換え（進み具合を表示）
2. 2回目以降、アカウントの図・CSVを使うとき → **解除**（パスフレーズ／パスキー／回復キー）
3. パスフレーズを忘れた → 回復キーで解除 → 新しいパスフレーズを設定
4. パスフレーズも回復キーもない → 読めないことを説明し、希望すればデータをすべて消して初めからやり直す
5. ログアウト・再読み込み → 鍵を忘れる

評価で使うCSVも、解除してから読み出して復号し、ブラウザ内の評価に渡す（今と同じ流れ）。

## 実装の置き場所

- `web/crypto/gsn_crypto.js`: WebCrypto での鍵の作成・包む・解く・暗号化・復号（ブラウザ内評価と同じく JS に置き、Dart から呼ぶ）
- `lib/crypto_service.dart`: 上の呼び出しと、keyring の読み書き・解除状態の管理
- `lib/cloud_diagram_service.dart`・`lib/cloud_csv_service.dart`: 暗号化した形で保存・読み出し
- `lib/crypto_dialogs.dart`: 初回設定・解除・回復・やり直しの画面
- `firestore.rules`: 上のルール

## 確かめること

- 暗号の部品のテスト（Node の WebCrypto）: 往復できる、パスフレーズ違いで失敗する、
  改ざん・ドキュメントの入れ替えを検知する、回復キーで解除できる
- ルールのテスト（Firestore エミュレータ）: 平文の書き込みを拒否する、他人のデータは読めない
- 画面のテスト（エミュレータ）: 初回設定 → 移行 → 再読み込み → 解除 → 回復キーで再設定

## 段階

| 段階 | 内容 |
|---|---|
| **1a** | 暗号の部品、keyring、初回設定・解除・回復の画面、図とCSVの暗号化、既存データの移行、ルール |
| **1b** | パスキーでの解除（PRF） |
| 2 | 版の履歴、CSVの一覧・削除画面、App Check、バックアップ |
| 3 | 共同研究者との共有、オフライン（暗号化したままブラウザに控えを置く） |

## 守れないもの（前提）

- 配っているエディタのコード自体が書き換えられた場合（Firebase・GitHub のアカウントは二段階認証で守る。
  Firebase Hosting に Content-Security-Policy を設定して、外部のスクリプトを読み込めないようにする）
- 利用者の端末がマルウェアに感染している場合
- パスフレーズと回復キーの両方をなくした場合のデータ（誰も戻せない）
